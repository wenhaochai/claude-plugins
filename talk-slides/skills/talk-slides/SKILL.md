# Talk slides

This skill produces a talk deck in the claude.ai Slides artifact format and keeps it right through many rounds of revision. It holds four things: the workflow, the slide rules the author settled on, a 14-slide template generated by tested layout builders, and a local audit that renders each slide in the Slides runtime. It was distilled from a paper talk that went through 23 published versions; `references/feedback.md` lists each piece of the author's feedback and the rule it became.

The Slides artifact type ships its own instructions for the file format and the Artifact calls. Follow them for the mechanics. This skill adds the design, the rules and the checks on top.

## Workflow

1. **Agree on the parts first.** A talk has a few parts, and each slide carries one idea. Turn every open choice into a short multiple-choice question: which slides to drop, which source to cite, whether a layout change is wanted. Cite only the sources the user names.
2. **Collect data from primary sources.** Keep the raw files next to the deck and recompute every plotted number from them. Re-fetch live leaderboards on the day you publish and put the read date in the source line.
3. **Start from the template.** Run `python3 scripts/build_template.py OUT` and copy the layouts the talk needs. Replace every bracketed string and every example number. Build new slides with the builders in `scripts/deckkit.py` so the geometry stays inside the audited budget.
4. **Write each slide to the rules below.** Everything you would say aloud goes into the speaker notes, in Chinese.
5. **Verify before every publish.** Run `python3 scripts/lint.py DECK_DIR`, then `python3 scripts/audit_render.py RUNTIME_DIR`, and look at every screenshot. Fix every finding, then run both again.
6. **Publish only what changed.** Read the live deck first and diff it against your copy so edits made in the page survive. Send the changed slide files in one Artifact call; send `project/deck.json` only when the order, sections or title change.
7. **Report in a few Chinese lines.** Give the version and link, what changed on which slide, and any number you corrected. Offer optional follow-ups as a multiple-choice question.

## Slide rules

**Titles**

- A title is a noun label that names what the slide shows: "Method", "Results", "Harbor-Index", "Vals Index v2", "Tasks and grading", "Commission task". Titles carry no claims or conclusions.
- A title the user gives verbatim stays as given, such as a source's own headline.
- The eyebrow names the part, as in "Part 3 · Public indices", and never repeats the title.
- Chart titles are short labels that say what the chart shows and carry no conclusion either. No headline is a comma-joined list of clipped phrases.

**Text**

- The slide holds labels, numbers and at most one short sentence per block. Explanations, caveats and context go into the notes.
- Wording stays plain: facts and numbers, no slogans and no elevated framing. Avoid the "X, not Y" construction, em dashes, and the word campaign outside verbatim quotes.
- Strengths and weaknesses of a work belong in the notes, which the author writes. The slide describes composition and principles.
- The cover subtitle states facts: title, author, date. The agenda lists the deck's actual parts, and the summary has one point per part plus one closing line.

**Figures**

- Show data as charts; a table becomes a chart. Show a headline number next to the figure that produced it, such as ρ beside its fit plot.
- The paper part takes three slides: the first page with the question it asks, one method figure, one comparison figure. Redraw the paper's figures in the deck style; the first page is the only screenshot.
- When a source publishes an official figure, use it as is.
- Every mark must carry data. Leave out decorative icons, big numerals with no quantity behind them, invented example distributions, side facts such as run cost or release counts, showcases of one model's numbers, aggregate categories with fuzzy edges, and categories whose meaning is unclear.
- Draw signed weights as magnitudes and label the two directions at the ends. State the source's sign convention in the notes.
- A leaderboard shows the top five with the uncertainty the source publishes, and the chart title names the interval. When the live board has fewer entries than the chart, say so under it.
- After drawing, check each chart against its source: order, sign, direction, units, the date of the data.

**Structure**

- One slide per method, index or example. Delete or merge slides the user marks as extra.
- The first slide of a new topic gives enough context to follow the examples that come after it: what the thing is, how it works, one real example.

**Speaker notes**

- Chinese, plain, at most 4,000 characters. First describe what the slide shows, then add sources, numbers and caveats.
- When a slide changes, update its notes in the same edit.

## Template

`scripts/build_template.py` writes these 14 slides. Each is a layout from the source talk with placeholders in place of its data.

| Slide | Layout | Builders |
|---|---|---|
| cover | dark title slide | `cover` |
| agenda | numbered parts | `agenda` |
| paper | first page and the question | `slide`, `image`, `label` |
| method | distribution with a highlighted band | `histogram` |
| results | fit scatter and a method comparison | `scatter`, `range_rows` |
| concept | source figure and signed weights | `image`, `diverging` |
| index-funnel | selection funnel, launch leaderboard, official figure | `funnel`, `board`, `image` |
| index-graders | weighted composition, grader shares, leaderboard | `composition`, `seg_bar`, `board` |
| index-legend | weight formula, grader legend bar, leaderboard with errors | `composition`, `legend_bar`, `board` |
| index-curves | fitted curves on one scale, counts, interval leaderboard | `curves`, `board` |
| topic-intro | four-step pipeline, a real task's checks, three scores | `pipeline`, `card`, `checklist`, `hbars` |
| example-1 | prompt, rubric, the one output that trips a check | `quote_card`, `rubric`, `hl` |
| example-2 | the deciding context, rubric, what several runs produced | `quote_card`, `rubric`, `outputs`, `hl` |
| summary | one point per part and a closing line | `summary` |

The builders take data and return HTML in the Slides subset. `board` takes rows of name, shown value, value and an optional interval; `seg_bar` takes shares with labels and an optional bracket over a run of segments; `curves` takes logistic curves with their midpoints and slopes. Each docstring states the width and height a builder uses.

## Runtime

The Slides runtime lays out a slide differently from a plain browser. `references/runtime.md` covers each case with its fix. The short list:

- An empty `<div>` with a width and no paint is dropped together with its gap, so the rest of the row shifts left. Offset with pinned children inside a sized host, or paint the spacer.
- A negative `left` or `top` is clamped to 0. Shift the plot down inside its host so every label keeps a positive offset.
- An overfull column shrinks its text. The audit flags any computed font size the slide never declares.
- A slide holds at most 200 elements and 15 nested divs, and a host holds at most 24 pinned children.
- An inline SVG stays under 52 KB and holds no `<text>`; its labels are pinned `<p>` elements over it.
- `align-items:baseline` adds height to rows with mixed font sizes; measure before trusting an estimate.
- `text-transform:uppercase` turns ρ into Ρ, so keep Greek letters out of uppercase labels.

## Audit

Run this before each publish and after every round of changes:

1. `lint.py` passes: file contract, subset limits, 24px text, no negative offsets, no dropped spacers. Read every warning: a template placeholder left on a slide or in the notes, or banned wording; a verbatim quote may trip the wording check.
2. `audit_render.py` passes on every changed slide: no shrink, no overflow, nothing outside the margins, no overlapping text.
3. Every screenshot looks right: alignment, labels clear of curves and bars, legends matching colors.
4. Every number on the slide matches the raw data, and live numbers were fetched today.
5. The notes match the slide, and the cover, agenda and summary match the deck.

## Files

- `scripts/deckkit.py`: design tokens and layout builders.
- `scripts/build_template.py`: writes the 14-slide template deck.
- `scripts/lint.py`: static checks on slide files.
- `scripts/audit_render.py`: renders slides in the runtime and reports shrink, overflow, margin and overlap findings.
- `references/runtime.md`: runtime behavior, the local audit setup, height budgets.
- `references/feedback.md`: the author's revision notes, in order, with the rule each produced.
